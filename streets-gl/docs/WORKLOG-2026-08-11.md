### 3. Memory (the 30 GB browser incident)
Root causes found by code audit, all fixed:
- **Tile eviction was effectively unbounded** — only out-of-frustum tiles beyond
  the cap were evicted, so a wide/high view kept every visible tile forever.
  Now: hard cap gates loading (`TileSystem.getNextTileToLoad`), eviction is
  demand-driven (frees room for queued tiles), plus a farthest-visible safety net.
- **Mega-buffer allocators never compacted** — frees punched holes, `used` only
  grew, every overflow DOUBLED the buffer (CPU mirror + GPU) permanently.
  Now: `MegaBufferAllocator.maintain()` (compact + shrink) runs from the render
  loop every 240 frames, one allocator per tick.
- **Projected + hugging geometry was mega-buffered but never drawn from there**
  (only extruded has a batch path) — two dead copies of most tile geometry.
  Removed those groups.
- **`TileObjectsSystem.buildingsList` never deleted entries** → entry per
  building ever seen. Fixed.
- **~250 startup images (92 MB PNGs) pinned forever** — released after GPU
  upload (`ResourceLoader.releaseImages()`, frame 300).
- **Default FPS cap 60** (was uncapped: 133 fps, GPU process at ~100% CPU).
- Tests: `megaBufferMaintenance.test.ts` (3) + updated integration tests.
- Measured (production build, 140 s full-throttle driving on the Israel-railways
  map with a 5-GLB consist): tiles flat at 150; allocator capacity oscillates
  9–23 MB (shrink works); renderer RSS sawtooths 750 MB–1.1 GB and RETURNS to
  ~740 MB; GPU process 240–360 MB. No ratchet.

  black screen + exception.
- `webglcontextlost` shows a "Graphics context lost — reload" overlay instead of

## Second round (same session): camera + local persistence (user reports)
- **Follow camera is now the default on every start path** — `startGame()`
  itself activates GameCameraSystem + snaps to the train. Previously only the
  UI click handlers did, so any other entry (or a missed path) left the map
  controls owning the camera: no follow, and the camera button "did nothing"
  (modes cycled internally with zero visual effect).
- `snapToTrain()` before the first physics frame defers to the first update
  (no lerp-in from world origin).
- Camera button re-activates defensively + shows a "Camera: Chase/Cab/Orbit"
  toast so cycling is always visible.
- **Browser-local settings persistence verified end-to-end** (fresh profile):
  settings-page clicks → localStorage → reload persists → game renders the
  saved 5-car consist incl. the flipped car. One real bug found + fixed: the
  game's 2s localStorage poll only applied slot/track/station changes — sound
  picks made while a game tab was open were silently dropped.
- Why a train can still "revert to default": (a) an EMPTY browser profile
  (incognito, another device, automated test browser) has no localStorage —
  you get the server default; (b) iOS Safari deletes script-writable storage
  (incl. localStorage) for sites not visited for ~7 days (ITP) — the likely
  historical cause on the iPad; (c) before today's data-seed sync, every
  redeploy changed catalog ids, so saved slots pointed at missing models and
  fell back to procedural cars. (c) is fixed by the sync discipline; (a)/(b)
  are browser behavior — the admin "save as server default" is the durable
  fallback.
- Server default consist is now a locomotive-led 4-car train (SD40-2 + city
  cars) — set live via the admin API and mirrored in data-seed/config.json.
